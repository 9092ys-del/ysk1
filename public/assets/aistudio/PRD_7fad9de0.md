## 1. 프로젝트 개요

### 1.1 제품 소개

아이콘카페의 신메뉴 **제주 구좌 유기농 당근케이크**를 홍보하고, 잠재
고객의 관심을 실제 매장 방문과 구매로 연결하는 모바일 우선 프로모션
웹페이지를 구축한다.

페이지에는 신메뉴를 중심으로 한 브랜드 스토리와 비주얼, 카페의 기본 메뉴
약 8종, 쿠폰 발급 기능, 매장 방문 안내를 포함한다. 고객이 쿠폰을
발급받으면 고유 바코드가 표시되며, 매장 직원이 이를 확인·사용 처리하면
동일 쿠폰을 다시 사용할 수 없어야 한다.

### 1.2 해결하려는 문제

-   신메뉴의 특징과 매력을 짧은 시간 안에 고객에게 전달한다.
-   건강한 재료와 자연스러운 단맛을 강조해 다이어트에 관심 있는 고객의
    호기심을 유도한다.
-   카페 인근 직장인과 20\~30대 고객에게 매력적인 디저트 선택지를
    제안한다.
-   쿠폰 혜택으로 첫 방문과 신메뉴 구매를 유도한다.
-   쿠폰의 중복 사용을 방지하고 직원이 매장에서 간편하게 검증할 수 있게
    한다.

### 1.3 주요 목표

1.  첫 화면에서 신메뉴와 핵심 메시지가 즉시 인지되도록 한다.
2.  신메뉴의 원재료와 맛에 대한 신뢰감 및 구매 욕구를 높인다.
3.  고객이 적은 단계로 쿠폰을 발급받을 수 있게 한다.
4.  발급된 쿠폰은 고유 식별값으로 관리하고 1회만 사용할 수 있게 한다.
5.  매장 기본 메뉴와 방문 정보를 쉽게 확인할 수 있게 한다.

## 2. 대상 고객

### 핵심 고객군

-   다이어트 및 식단 관리에 관심이 있는 고객
-   카페 인근 직장인
-   20\~30대 카페·디저트 소비자
-   새로운 시즌 메뉴와 감각적인 카페 브랜드 경험을 선호하는 고객

### 고객의 기대

-   건강한 재료를 사용한 디저트에 대한 관심
-   설탕을 넣지 않았지만 맛있고 달콤한 디저트에 대한 호기심
-   보기 좋고 먹음직스러운 제품 사진
-   간단하고 명확한 쿠폰 혜택
-   모바일에서 빠르고 편리한 쿠폰 발급 및 제시 경험

## 3. 브랜드 및 신메뉴 포지셔닝

### 3.1 브랜드

-   카페명: **아이콘카페**
-   브랜드 페이지 분위기: 산뜻함, 자연스러움, 건강함, 달콤함, 감각적인
    카페 무드

### 3.2 신메뉴

-   메뉴명: **제주 구좌 유기농 당근케이크**
-   핵심 원재료 메시지: 제주도 구좌 지역의 유기농 당근
-   단맛의 특징: 설탕을 넣지 않고 당근과 과일 자체의 단맛을 활용
-   고객에게 전달할 핵심 가치: 건강한 재료와 자연스러운 달콤함을 함께
    즐기는 디저트

### 3.3 핵심 카피 방향

메인 카피 제안:

> 건강한 달콤함을 만나다.

서브 카피 제안:

> 제주 구좌 유기농 당근과 자연이 선물한 달콤함.\
> 설탕 없이, 당근과 과일 본연의 단맛을 즐겨보세요.

보조 카피 제안:

> 오늘의 디저트는 조금 더 산뜻하게.

**표현 유의사항:** 실제 제조 방식과 원재료가 확인되기 전에는 `무가당`,
`설탕 무첨가`, `당류 0g`, `다이어트에 좋다`, `저칼로리` 등의 표현을
임의로 확정하지 않는다. 특히 무가당 표시의 적합성은 제품 배합과 관련
표시 기준을 확인한 뒤 결정한다. 당근과 과일 자체의 당류가 존재할 수
있으므로 영양·건강 효과를 과장하지 않는다.

## 4. 디자인 및 비주얼 가이드

### 4.1 전체 디자인 방향

산뜻하고 밝은 인상을 주는 현대적인 카페 프로모션 페이지로 제작한다.
20\~30대 고객이 선호할 만한 감각적인 편집 디자인을 지향하되, 메뉴와 쿠폰
정보는 쉽게 읽히도록 구성한다.

### 4.2 컬러 가이드

  용도   권장 색상             사용 방향
  ------ --------------------- --------------------------
  메인   세이지 그린           브랜드 포인트, 주요 버튼
  배경   크림 화이트           넓은 배경, 카드
  강조   당근 오렌지           신메뉴 강조, 작은 포인트
  본문   짙은 그린 또는 차콜   제목과 본문 가독성
  보조   연한 그린             구획, 배경 면

정확한 HEX 값은 실제 화면 시안 단계에서 확정한다.

### 4.3 이미지 스타일

-   밝은 자연광과 부드러운 그림자
-   신선한 당근, 과일, 자연 소재를 연상시키는 연출
-   크림 화이트와 그린 계열의 정돈된 배경
-   먹음직스러운 질감이 잘 드러나는 디저트 클로즈업
-   메뉴별 이미지의 조명, 구도, 배경 톤을 일관되게 유지
-   과도한 장식보다 제품 자체가 돋보이는 구성

### 4.4 이미지 제작 요구사항

카페 기본 메뉴 약 8종과 신메뉴의 이미지를 준비한다. 사용 가능한 실제
상품 사진이 없다면 AI로 메뉴별 이미지를 새로 생성한다.

AI 생성 이미지는 실제 판매 메뉴와 다른 토핑·재료·제공 형태를 보여주지
않도록 메뉴 정보를 기준으로 검수한다. 이미지 생성 후 실제 제품과 차이가
큰 경우 홍보 이미지로 사용하지 않는다.

## 6. 쿠폰 프로모션 및 사용자 흐름

### 6.1 프로모션 목적

신메뉴 구매와 신규 고객의 매장 방문을 유도하기 위해 첫 방문 고객에게
아메리카노 무료 혜택을 제공한다.

### 6.2 현재 합의된 혜택 방향

-   대상: 아이콘카페 첫 방문 고객
-   조건: 신메뉴 당근케이크 구매
-   혜택: 아메리카노 1잔 무료
-   고객 행동: `신메뉴 쿠폰 받기` 버튼을 눌러 쿠폰 발급
-   쿠폰 형태: 고유 쿠폰 코드가 포함된 바코드

쿠폰의 유효기간, 발급 제한, 아메리카노 사이즈·옵션 및 다른 할인과의 중복
여부는 결정이 필요하다.

### 6.3 고객 쿠폰 발급 흐름

1.  고객이 랜딩페이지에서 `신메뉴 쿠폰 받기` 버튼을 누른다.
2.  필요한 경우 첫 방문 고객 및 사용 조건을 안내한다.
3.  시스템이 고유 쿠폰 ID와 추측하기 어려운 고유 토큰을 생성한다.
4.  쿠폰 정보를 서버에 저장한다.
5.  고객 화면에 쿠폰 혜택, 바코드, 쿠폰 코드, 유효기간 및 사용 안내를
    표시한다.
6.  고객은 매장 직원에게 쿠폰을 제시한다.

발급된 쿠폰은 고객이 다시 방문해도 동일한 쿠폰을 새로 발급받을 수 있는지
정책을 별도로 적용해야 한다. 기본 권장안은 고객 식별 방식과 발급 제한
정책이 정해질 때까지 중복 발급 방지 규칙을 확정하지 않는 것이다.

### 6.4 바코드 표시

-   쿠폰마다 고유한 식별값을 사용한다.
-   바코드는 서버에서 검증 가능한 쿠폰 토큰 또는 쿠폰 ID를 인코딩한다.
-   바코드 아래에 사람이 읽을 수 있는 쿠폰 코드를 함께 표시한다.
-   쿠폰 혜택, 사용 조건, 발급일, 유효기간을 표시한다.
-   사용 완료된 쿠폰은 `사용 완료` 상태를 명확하게 보여준다.
-   단순히 화면에 바코드 이미지를 띄우는 것으로 사용 완료 처리하지
    않는다.

### 6.5 직원용 쿠폰 검증 및 사용 처리

권장 구현안은 직원 전용 관리자 화면에서 휴대폰 카메라로 고객 바코드를
스캔하는 방식이다. 이 방식은 제안 사항이며 최종 확정은 필요하다.

권장 흐름:

1.  직원이 인증된 관리자 화면에 로그인한다.
2.  쿠폰 스캔 기능을 연다.
3.  고객이 제시한 바코드를 카메라로 스캔한다.
4.  서버가 쿠폰 ID, 발급 상태, 유효기간, 사용 여부를 확인한다.
5.  유효한 쿠폰이면 혜택과 사용 조건을 직원에게 보여준다.
6.  직원이 사용 처리를 확정한다.
7.  서버가 쿠폰을 원자적으로 사용 완료 상태로 변경한다.
8.  고객 화면과 직원 화면에 사용 완료 결과를 표시한다.

### 6.6 중복 사용 방지 필수 요건

-   쿠폰 사용 여부는 클라이언트가 아닌 서버에서 최종 판단한다.
-   사용 처리는 데이터베이스의 원자적 업데이트 또는 트랜잭션으로
    수행한다.
-   이미 사용된 쿠폰은 다시 사용 처리할 수 없어야 한다.
-   같은 쿠폰을 두 직원이 거의 동시에 스캔하더라도 한 번만 성공해야
    한다.
-   사용 완료 시각과 처리 직원 계정을 기록한다.
-   위조되거나 존재하지 않는 쿠폰 코드는 거부한다.
-   만료 쿠폰은 거부한다.
-   직원용 사용 처리 기능은 인증된 직원만 접근할 수 있어야 한다.
-   고객 브라우저에서 쿠폰 상태를 임의로 변경할 수 없어야 한다.

### 6.7 쿠폰 상태

  상태        설명
  ----------- --------------------------------------
  발급됨      쿠폰이 정상 발급된 상태
  사용 완료   매장에서 정상적으로 사용 처리된 상태
  만료됨      유효기간이 지난 상태
  취소됨      관리자 정책에 따라 취소된 상태

### 6.8 쿠폰 오류 및 예외 상황

-   이미 사용된 쿠폰: `이미 사용된 쿠폰입니다.`
-   만료된 쿠폰: `쿠폰 유효기간이 만료되었습니다.`
-   유효하지 않은 코드: `유효한 쿠폰을 확인할 수 없습니다.`
-   네트워크 오류: 사용 처리 여부를 단정하지 않고 서버 상태를 다시
    확인하도록 안내
-   카메라 권한 거부: 직원이 쿠폰 번호를 직접 입력할 수 있는 대체 방법
    제공 권장

## 8. 데이터 및 백엔드 요구사항

### 8.1 기본 원칙

쿠폰을 1회만 사용할 수 있게 하려면 영속적인 서버와 데이터베이스가
필요하다. 프론트엔드만으로 구현하거나 브라우저의 로컬 상태만 이용하는
방식은 실제 매장 운영용 중복 사용 방지에 적합하지 않다.

Google AI Studio에서 프론트엔드와 백엔드를 구현하되, 실제 배포 환경에
맞는 인증·데이터베이스·서버 기능을 연결한다. Firebase 등 Google 생태계의
백엔드 사용을 우선 검토할 수 있으나 구체적인 기술 선택은 구현 단계에서
확정한다.

### 8.2 쿠폰 데이터 모델 제안

`coupons`

  필드                         설명
  ---------------------------- -----------------------------------------
  id                           쿠폰 고유 ID
  tokenHash 또는 secureToken   검증용 고유 토큰(보안 설계에 따라 저장)
  couponType                   쿠폰 종류
  status                       issued / redeemed / expired / cancelled
  issuedAt                     발급 시각
  expiresAt                    만료 시각
  redeemedAt                   사용 완료 시각
  redeemedBy                   사용 처리 직원 ID
  customerReference            고객 식별값(정책 확정 시)

`staff`

  필드          설명
  ------------- ------------------
  id            직원 ID
  displayName   표시 이름
  role          직원 또는 관리자
  active        계정 활성 여부

`couponEvents`

  필드        설명
  ----------- ---------------------
  id          이벤트 ID
  couponId    대상 쿠폰
  eventType   발급, 사용, 취소 등
  actorId     처리 주체
  createdAt   처리 시각
  metadata    추가 기록

실제 구현에서는 개인정보를 최소한으로 수집하고, 쿠폰 토큰이 URL이나
로그에 불필요하게 노출되지 않도록 한다.

### 8.3 서버 검증 예시 로직

-   쿠폰 토큰을 입력받는다.
-   서버에서 해당 쿠폰을 조회한다.
-   쿠폰 존재 여부, 상태, 만료 시각을 확인한다.
-   사용 처리 시 트랜잭션 또는 조건부 업데이트를 실행한다.
-   `status = issued`인 경우에만 `redeemed`로 변경한다.
-   업데이트 성공 여부를 반환한다.
-   이미 다른 요청이 먼저 사용 처리했다면 실패 응답을 반환한다.

## 9. 비기능 요구사항

### 9.1 반응형 및 모바일 우선

-   모바일 화면에서 우선적으로 설계한다.
-   태블릿과 데스크톱에서도 레이아웃이 자연스럽게 확장되어야 한다.
-   쿠폰 바코드가 휴대폰 화면에서 선명하고 충분히 크게 표시되어야 한다.
-   주요 버튼은 터치하기 쉬운 크기로 제공한다.

### 9.2 성능

-   첫 화면의 신메뉴 이미지를 우선 로딩한다.
-   메뉴 이미지는 적절한 크기와 포맷으로 최적화한다.
-   이미지 로딩 중 레이아웃이 크게 흔들리지 않도록 한다.
-   불필요한 애니메이션과 무거운 효과는 피한다.

### 9.3 접근성 및 사용성

-   충분한 텍스트 대비를 유지한다.
-   버튼과 입력 요소에 명확한 이름을 제공한다.
-   이미지에 적절한 대체 텍스트를 제공한다.
-   색상만으로 쿠폰 상태를 구분하지 않는다.
-   오류 메시지는 원인과 다음 행동을 쉽게 이해할 수 있게 작성한다.

### 9.4 보안

-   관리자 기능에 인증 및 권한 검사를 적용한다.
-   쿠폰 사용 처리는 서버에서만 수행한다.
-   고유 쿠폰 토큰을 추측하기 어렵게 생성한다.
-   동시 사용 요청을 안전하게 처리한다.
-   개인정보 수집은 서비스 운영에 필요한 최소 범위로 제한한다.
-   비밀키와 관리자 인증 정보를 클라이언트 코드에 노출하지 않는다.

## 15. 최종 제품 방향 요약

아이콘카페의 신메뉴 홍보 페이지는 **제주 구좌 유기농 당근과 당근·과일
본연의 단맛을 강조한 당근케이크**를 중심으로, 산뜻하고 감각적인 브랜드
경험을 제공한다.

고객은 페이지에서 신메뉴와 기본 메뉴를 확인하고 쿠폰을 발급받아 매장에서
제시한다. 직원은 인증된 관리 화면에서 바코드를 확인하고 사용 처리한다.
쿠폰은 서버에 상태가 저장되며 한 번 사용되면 재사용할 수 없다.

핵심 성공 기준은 다음 세 가지다.

1.  신메뉴가 매력적으로 보이고 구매하고 싶어지는가?
2.  고객이 쿠폰을 쉽고 편리하게 발급받을 수 있는가?
3.  매장에서 쿠폰을 안전하게 검증하고 중복 사용을 막을 수 있는가?
